# Topic: Endpoint security and EDR

## Meta-Summary

The records portray endpoint security as a contest over **visibility, trust, and control at increasingly lower layers of the host**. Conventional EDR remains important, but the collection repeatedly challenges assumptions that process trees, command-line logs, memory scans, signed drivers, security agents, and operating-system event streams provide complete or trustworthy evidence. ETW streams can be polluted or exhausted; COM, WinRT, WMI, enclaves, GPU-private memory, firmware, and kernel drivers can move execution outside familiar observation paths; and attackers can repurpose trusted defensive components against other defenses [record_id:17] [record_id:2052] [record_id:2611] [record_id:2622] [record_id:2862] [record_id:2897] [record_id:2936].

Windows dominates the collection, especially research on kernel exploitation, EDR bypass, protected processes, signed drivers, recovery and boot components, and living-off-the-land execution. macOS is nevertheless becoming a first-class endpoint research area, with work on Apple Endpoint Security, XProtect Remediator, malware analysis, management-plane abuse, identity theft, GPU visibility gaps, and surviving forms of dylib hijacking [record_id:8] [record_id:77] [record_id:1964] [record_id:1987] [record_id:2793] [record_id:2897] [record_id:2912]. Linux coverage is smaller and divides between kernel exploitation, eBPF/LSM enforcement, container syscall controls, shell telemetry, and weaknesses caused by ordinary multi-user process visibility [record_id:12] [record_id:35] [record_id:169] [record_id:2090] [record_id:2617].

A second major strand asks how endpoint telemetry can be made operationally useful. Research applies process-relationship graphs, registry mining, shell-language parsing, alert clustering, anomaly detection, continual learning, emulation, and memory forensics to improve detection while reducing false positives [record_id:183] [record_id:191] [record_id:192] [record_id:206] [record_id:221] [record_id:2752]. At the same time, several records warn that alert severity, model confidence, dataset labels, and anomaly scores can be unreliable or actively manipulated [record_id:59] [record_id:202] [record_id:230] [record_id:240] [record_id:2420].

Overall, the collection supports a shift from treating EDR as a self-contained product toward treating endpoint defense as an **ecosystem of sensors, enforcement points, identity controls, management planes, firmware, developer tooling, and analyst workflows**. The strongest defensive message is that no single telemetry source or trust label is sufficient.

## Research Landscape

The corpus spans 2018–2026 and consists primarily of conference abstracts from Black Hat, DEF CON, BSides Las Vegas, CAMLIS, and AI-oriented events. The later records—especially those from 2025 and 2026—are dominated by offensive demonstrations, reverse engineering, tools, vulnerability disclosures, and claims of bypassing commercial EDR products. Earlier CAMLIS records contain more methodological detail about datasets, model architectures, experiments, and evaluation metrics. This creates two complementary but uneven evidence streams:

1. **Offensive systems research** identifies concrete blind spots and attack primitives, often through a proof of concept or live demonstration.
2. **Applied security machine learning** explores how to classify malware and host activity, usually with clearer discussion of datasets and metrics but less evidence about long-term production deployment.

Windows is the central platform. The records cover ETW, AMSI, DPAPI, LAPS, RPC, COM/DCOM, WMI, WinRE, Secure Boot, VBS, PPL, Windows Defender drivers, AFD, WSUS, PnP, AppContainers, WinRT, MSIX, kernel drivers, and bootkits. The recurring finding is not simply that vulnerabilities remain, but that interactions between trusted components create attack surfaces that are poorly represented in standard process-centric telemetry [record_id:28] [record_id:36] [record_id:2016] [record_id:2082] [record_id:2608] [record_id:2613] [record_id:2873] [record_id:2950].

macOS research covers both native defenses and their limitations. Records examine XProtect’s internal remediation logic, Apple’s Endpoint Security framework, malware wrapped around embedded scripts, Jamf as a remote execution and lateral-movement plane, PRT-cookie theft, Keychain compromise, and modern malware delivery [record_id:8] [record_id:77] [record_id:1964] [record_id:1987] [record_id:2128] [record_id:2793] [record_id:2860]. Several newer records focus on under-observed execution or storage surfaces, including Apple AI frameworks, Metal GPU memory, scheduling and XPC behavior, and dynamic-library loading [record_id:4] [record_id:2635] [record_id:2897] [record_id:2912].

Linux and cloud-native endpoint research is less numerous but technically diverse. It includes TLB side channels against kernel objects, eBPF-based DNS prevention, stateful syscall enforcement for containers, shell-session analysis, and secret leakage through default process-inspection behavior [record_id:12] [record_id:35] [record_id:169] [record_id:2090] [record_id:2617]. Android appears through Zygote injection, mobile-security-product vulnerabilities, and adversarial manipulation of forensic extraction [record_id:2096] [record_id:2548] [record_id:2576].

The records rarely discuss “XDR” as a distinct architecture. Instead, they implicitly describe XDR’s problem space: correlating endpoint processes, cloud credentials, identity tokens, network behavior, software supply chains, management systems, and analyst decisions. Likewise, Sysmon is not a major explicit subject. ETW, Endpoint Security, AMSI, process ancestry, kernel events, and memory artifacts receive substantially more attention.

## Major Themes And Trends

### Telemetry is an attack surface, not neutral ground

The clearest challenge to telemetry integrity comes from work showing that unprivileged processes can inject custom ETW events, generate misleading attack traces, or exploit event-capping behavior so that Microsoft Defender for Endpoint ignores later events. This can be useful for safe blue-team simulation, but it also allows attackers to deceive analysts or blind collection [record_id:17]. Android forensic tooling faces a parallel trust problem: extraction software may assume that a compromised device returns faithful evidence even when device-side countermeasures silently alter or destroy data [record_id:2096].

Other records focus on telemetry absence rather than falsification. COM and WinRT can perform actions analogous to monitored command-line tools while producing different logging, lineage, and network evidence [record_id:2936]. Ephemeral COM registration can create a fresh identity, activate code inside `dllhost.exe`, erase registry artifacts, and sever visible ancestry from the attacker’s process [record_id:2622]. Custom WMI providers similarly move post-exploitation into `WMIPrvSE.exe`, outside the heavily monitored `Win32_Process Create` and event-subscription patterns [record_id:2862]. GenAI coding assistants add another attribution problem: commands may be executed for a user through multi-level AI-spawned ancestry chains without standardized telemetry that explains what the model requested or observed [record_id:2341].

The implication is that endpoint telemetry needs explicit integrity, provenance, and completeness models. A process event should not automatically be treated as ground truth merely because it came through a native provider, and an absent event should not be interpreted as proof that an action did not occur.

### EDR evasion increasingly repurposes trusted infrastructure

Many newer records do not depend on conventional malware hiding from signatures. They instead weaponize components already trusted by the operating system or security stack. Windows Defender’s signed Boot-Time Removal driver can allegedly be supplied with valid transactions and used as a Ring 0 file-and-registry operation engine, including to disable security products [record_id:2611] [record_id:2866]. “Bring-Your-Own-EDR” abuses an EDR installer’s trust and PPL handling to create self-protected malware [record_id:2870]. Another chain uses WerFaultSecure and Microsoft System Guard features to obtain protected-process and kernel tampering primitives [record_id:2953].

This is related to, but broader than, Bring Your Own Vulnerable Driver. Traditional BYOVD remains prominent in offensive workshops and driver-reversing research [record_id:2750] [record_id:2763]. The newer trend is to avoid a vulnerable third-party driver altogether and use legitimate, Microsoft-signed remediation or security functionality as the primitive. Similarly, native tools, weak anti-tampering, and misconfiguration can reportedly disable Defender or Zscaler without sophisticated exploits [record_id:2407].

The same inversion appears outside EDR proper. WSUS can become an organization-wide implant-delivery platform [record_id:2613]; Jamf APIs can enable undetected execution and lateral movement across managed Macs [record_id:77]; a highly privileged GlobalProtect endpoint agent introduces privilege-escalation and VPN-bypass risk [record_id:54]; and Trend Micro’s mobile security product itself exposes reports and potentially exploitable agent behavior [record_id:2576]. Defensive infrastructure therefore expands both protection and blast radius.

### Process-centric visibility is increasingly insufficient

Traditional EDR analytics emphasize process creation, command lines, parent-child relationships, and memory mappings. Those remain valuable: ProblemChild shows how parent-child graphs reveal living-off-the-land activity that looks benign in isolation [record_id:221], and GenAI observability work argues for correlating multi-level ancestry [record_id:2341]. But the offensive records repeatedly find execution paths that weaken these signals.

VBS enclaves offer memory isolated even from the hosting process and kernel, creating a prospective refuge for malware [record_id:2052]. Metal `StorageModePrivate` places data in GPU-managed pages outside Mach VM and therefore outside ordinary macOS process-memory inspection and Endpoint Security mmap events [record_id:2897]. Physical-memory primitives are proposed for bypassing modern EDR and maintaining low-level persistence [record_id:2009]. Firmware and boot-stage implants operate before, beneath, or independently of OS-level defenses [record_id:41] [record_id:1967]. COM, WinRT, WMI, AppContainer services, and package-management infrastructure can perform attacker-relevant actions without the process trees expected by CLI-oriented detections [record_id:2622] [record_id:2862] [record_id:2936] [record_id:2950].

The trend is toward analytics that combine process data with module loads, RPC/DCOM activation, registry transactions, driver operations, GPU allocations, firmware state, management-plane actions, and identity events.

### Detection quality is limited as much by workflow as by sensors

The records repeatedly identify SOC overload as a security weakness. Attackers can choose techniques that generate only medium- or low-severity alerts, or cause products to downgrade or suppress activity, relying on analysts to ignore the resulting noise [record_id:59]. Event clustering attempts to reduce this burden by grouping similar alerts, using prior resolutions to prioritize new cases, and exposing inconsistent decisions [record_id:192]. The proposed system processes approximately 1.5 million events and 3,500 alerts on average, although it is explicitly described as work in progress.

A later empirical analysis of 95 red-team engagements argues that real operations do not follow a clean kill chain. Operators repeatedly cycle between discovery and credential access; lateral movement fails frequently; and those failures leave artifacts that are rarely monitored [record_id:2722]. This suggests that detections organized only around successful, linear ATT&CK sequences may miss useful evidence. It also reinforces the need to preserve failed commands, authentication attempts, name-resolution activity, and partial execution traces.

### Machine learning is moving from isolated classification toward resilient pipelines

The machine-learning records show a progression from file classification toward context, uncertainty, and operational adaptation. Early work uses AMSI chunks to score and stop PowerShell scripts [record_id:216], semantic tags to describe malware capabilities rather than force every sample into a vendor-specific family [record_id:219], and ransomware I/O behavior to support early blocking [record_id:230]. Other work improves shell parsing [record_id:191], mines registry behavior [record_id:183], models parent-child processes [record_id:221], and detects anomalous Unix shell sessions using DistilBERT [record_id:169].

Datasets are a major enabling component. BETH supplies more than eight million host events across 23 systems for anomaly and out-of-distribution research [record_id:194]. SOREL-20M provides nearly 20 million files, labels, metadata, tags, baselines, and roughly ten million disarmed samples [record_id:195]. Yet labels and distributions drift. VirusTotal labels change as engines improve, motivating strategic rescanning [record_id:240]. Open-set malware classification work argues that unsupported samples should be recognized as unknown and routed to more expensive analysis rather than accepted with unjustified confidence [record_id:202]. MADAR uses diversity-aware replay to reduce catastrophic forgetting across evolving Windows and Android malware [record_id:121].

Recent work also questions anomaly detection’s usual role. One pipeline uses anomaly detection not as the final detector but to find diverse benign command lines that an LLM labels for supervised training, reducing false positives [record_id:89]. Lightweight emulation combines API-call and memory telemetry with static features and reportedly corrects up to half of the errors induced by static models [record_id:206]. Memory forensics for Go malware reconstructs runtime strings, goroutines, arguments, and execution state that static reverse engineering misses [record_id:2752].

The adversarial side is equally prominent. A ransomware simulator altered benign I/O around encryption to bypass high-accuracy classifiers, showing that offline metrics did not translate directly into robust online detection [record_id:230]. Minor malware modifications reportedly lower both ML and traditional detection scores [record_id:2420]. Specialist language models are being trained specifically for AV/EDR evasion [record_id:62], while agentic PowerShell malware can dynamically generate in-memory code and metamorphic obfuscation—although its authors concede that current agentic malware offers limited advantage over traditional techniques [record_id:2391].

### The endpoint perimeter now includes developer and management systems

Several records frame developer laptops as unusually high-value endpoints because they hold cloud keys, repository access, package-publishing credentials, SSH keys, and secrets for multiple organizations. An empirical study of attacker infrastructure reports approximately 96,000 infected developer workstations and active credentials affecting more than 175 organizations, highlighting a “contractor multiplier” in which one endpoint connects unrelated client environments [record_id:2660]. The npm-focused records describe malicious packages, fake recruitment, account takeover, self-replicating package behavior, and the need to scope these incidents using EDR and SIEM telemetry [record_id:2731] [record_id:2754].

This theme changes endpoint risk modeling. The relevant question is not only what data resides locally, but what downstream production, cloud, CI, package, and customer systems the endpoint can authorize.

### macOS has moved from niche coverage to specialized endpoint engineering

The macOS records collectively reject the old assumption that built-in Apple controls are sufficient. XProtect Remediator contains sophisticated logic—including OCR-assisted detection, a custom Swift DSL, and provenance artifacts—but requires reverse engineering to understand its coverage [record_id:8]. Apple Endpoint Security provides powerful monitoring and authorization, yet developers must correctly handle caching, deadlines, mute inversions, and new TCC events [record_id:1964]. Modern malware abuses AppleScript, `osascript`, Keychain access, Launch Agents, signed/notarized packages, fake recruiters, and ClickFix-style terminal instructions [record_id:2793].

Other attacks target surrounding identity and platform mechanisms: Jamf management APIs [record_id:77], Intune’s macOS SSO implementation and PRT cookies [record_id:1987], iCloud Keychain [record_id:2860], and surviving dylib-hijacking opportunities [record_id:2912]. Apple’s own AI and media frameworks may provide payload embedding and covert C2 channels [record_id:4], while GPU-private memory creates a potential inspection gap [record_id:2897]. The macOS defensive problem is therefore no longer merely porting Windows signatures; it requires platform-specific telemetry, reverse engineering, and behavioral models.

## Methods, Tools, And Approaches Discussed

The collection describes several recurring research workflows.

**Reverse engineering and dynamic instrumentation** are used to understand opaque endpoint components. XProtect Remediator analysis required custom static and dynamic tools for stripped Swift binaries [record_id:8]. Windows LAPS research combines PDB symbols, static analysis, Frida, and Microsoft Detours to intercept and manipulate client-side password rotation [record_id:2082]. BTR.sys research reconstructs proprietary encrypted transaction formats and introduces BTR_CLI [record_id:2611] [record_id:2866]. macOS script analysis avoids low-level disassembly by identifying wrapper frameworks such as PyInstaller, Appify, Tauri, and Platypus and extracting their embedded scripts [record_id:2128].

**Fuzzing and composition-oriented vulnerability discovery** appear in boot, kernel, and platform research. Secure Boot research builds UEFI debugging and fuzzing frameworks and reports 31 CVEs across network, registry, and filesystem components [record_id:28]. AFD research treats transports and code paths as composable “gadgets,” finding bugs that are not visible when each driver is reviewed in isolation [record_id:2608]. AI-assisted macOS vulnerability research proposes triaging source-code diffs and prioritizing fuzzing targets in Apple’s partially open-source codebase [record_id:2356]. GCD/XPC research maps queue misuse and scheduler behavior into a repeatable concurrency bug class and corresponding detection signals [record_id:2635].

**Host-native telemetry analysis** includes AMSI script chunks [record_id:216], registry-key normalization and frequent-item-set mining [record_id:183], process graphs [record_id:221], ETW provider configurations [record_id:2622], and Endpoint Security events for TCC and dynamic-library loads [record_id:1964] [record_id:2912]. Shell-focused work uses a purpose-built preprocessing library rather than conventional NLP tokenization, improving reported F1 from 0.392 to 0.874 [record_id:191]. DistilBERT is applied to Unix shell sessions with supervised and unsupervised methods [record_id:169].

**Memory and runtime analysis** bridge static and full sandbox approaches. SpeakEasy emulation captures API calls, allocations, memory accesses, files, and network activity on-device [record_id:206]. Memory-forensics techniques cluster live processes, libraries, drivers, and kernel modules to find sophisticated in-memory threats [record_id:250]. Volatility 3 plugins reconstruct Go runtime metadata, strings, goroutines, and arguments from memory [record_id:2752].

**Kernel and inline enforcement** are proposed where post-hoc detection is too slow. An eBPF-based DNS framework performs kernel-level protocol parsing, dynamic policy enforcement, event streaming, and process termination, aided by a userspace deep-learning model [record_id:35]. The container-defense work uses thread-level state tracking, LSM-BPF hooks that reject operations before kernel completion, and OCI hooks that load policies before container startup [record_id:2617]. These records emphasize prevention at the operation boundary rather than alerting after an asynchronous kill signal.

**Adversary emulation and iterative evasion testing** are common operational methods. One workshop puts participants in an enterprise lab containing AV, EDR, proxies, and SIEM and maps exercises to ATT&CK [record_id:2562]. Another uses Elastic Defend’s open rules to show why loaders are blocked, then iteratively introduces module stomping, stack spoofing, indirect syscalls, Havoc customization, and BYOVD [record_id:2750]. Anti-cheat research uses grey-box “prod the bear” testing and underground-market economics to compare defensive resilience [record_id:90], while a related record explores false bans and machine-fingerprint poisoning [record_id:1951]. The broader comparison between cheat loaders and enterprise malware argues that game-security ecosystems can teach EDR practitioners about adversarial persistence and defense [record_id:2017].

**Physical and peripheral attack methods** extend endpoint compromise beyond software delivery. Records discuss keyboard keylogging, RF emanations, and acoustic inference [record_id:1938]; DuckyScript and O.MG HID payload development [record_id:2453] [record_id:2729]; remote Meshtastic-triggered HID injection [record_id:2938]; and Windows PnP auto-install behavior triggered by physical or RDP-redirected USB devices [record_id:2873]. Meshtastic is also used as a low-bandwidth C2 channel for Linux hosts in constrained environments [record_id:1895].

## Notable Talks, Records, And Evidence

Several records are especially representative of the topic.

The ETW-manipulation research is central because it attacks the evidentiary foundation of Windows EDR rather than merely hiding one process. Its claim that unelevated user-mode code can inject telemetry and induce event capping makes it relevant to detection testing, adversary simulation, and forensic trust [record_id:17]. The severity is substantial, but the abstract does not provide independent reproduction data or quantify which product versions remain affected.

The alert-fatigue record complements this at the SOC layer. It claims that common attack techniques can be adjusted to produce mostly medium- and low-severity alerts across CrowdStrike, SentinelOne, and Defender for Endpoint, preserving attack effectiveness while exploiting operational prioritization [record_id:59]. This is strong as a multi-product research claim but remains abstract-level evidence without configurations, sample sizes, or false-negative rates.

The BTR.sys research is important because it represents a shift from BYOVD toward “bring your own trusted primitive.” The same core work appears in Black Hat and DEF CON records, strengthening confidence that it is a substantive research program but not providing independent corroboration because the records describe the same talk and authors [record_id:2611] [record_id:2866]. BitUnlocker is another duplicated conference presentation rather than two separate findings [record_id:36] [record_id:1870], as is ReVault [record_id:48] [record_id:1942].

The macOS Endpoint Security presentation is one of the strongest defense-oriented platform records. It focuses on implementation details that can directly cause missed events or authorization failures and validates examples against sophisticated malware [record_id:1964]. XProtect reverse engineering provides complementary insight into Apple’s native detection logic and identifies provenance data potentially useful to third-party forensic tools [record_id:8].

Among the machine-learning records, the shell-language preprocessing result is unusually concrete, reporting a substantial F1 improvement over conventional tokenization [record_id:191]. The emulation-assisted malware work also provides useful quantitative evidence, including datasets, model families, operational tradeoffs, and a reported correction of up to 50% of static-model errors [record_id:206]. SOREL-20M and BETH are foundational because they make large-scale experimentation possible, although their suitability depends on the research task and temporal representativeness [record_id:194] [record_id:195].

The ransomware-resilience study is notable for explicitly showing the gap between high test accuracy and online robustness. Its simulated ransomware bypassed the detector with small changes to I/O patterns, motivating adversarial training and model explanation [record_id:230]. This is more informative than a simple accuracy claim because it examines failure under adaptation.

The developer-compromise study offers the corpus’s strongest empirical evidence about endpoint blast radius: attacker-controlled infrastructure, triage of more than 1,500 hosts, approximately 96,000 infections in the broader campaign, and verified credentials across many organizations and sectors [record_id:2660]. Its stated limitations—identity-only credential validation and no production access—are important and appropriate. The red-team knowledge-graph study similarly provides concrete operational counts across 95 engagements, though its findings need methodological review once the underlying dataset and toolkit are available [record_id:2722].

Finally, the collection contains unusually ambitious low-layer claims. Shade BIOS proposes OS-independent firmware malware [record_id:41]; VBS enclave malware claims execution beyond ordinary EDR reach [record_id:2052]; Metal memory laundering claims complete evasion with millisecond CPU exposure [record_id:2897]; and pure bootkit/rootkit tooling exposes pre-boot networking, kernel C2, hiding, and keylogging [record_id:1967]. These are strategically important, but “undetectable” and “100% evasion” claims should be treated cautiously until independently reproduced across hardware, OS versions, and products.

## Gaps, Limits, And Open Questions

The principal limitation is that most records are **conference abstracts rather than full technical reports**. They frequently promise tools, demonstrations, CVEs, or detection rules without including enough information to assess reproducibility, affected versions, test configurations, or vendor remediation. Product-evasion claims are especially sensitive to sensor version, policy mode, cloud analytics, and tenant configuration.

Independent replication is scarce. Multiple conference appearances sometimes create apparent repetition without independent evidence: BitUnlocker [record_id:36] [record_id:1870], ReVault [record_id:48] [record_id:1942], and BTR Reforged [record_id:2611] [record_id:2866] are repeated presentations of the same underlying work. Anti-cheat records are related but focus on different offensive and defensive dimensions [record_id:90] [record_id:1951].

The collection does not provide a systematic comparison of commercial EDR products. It offers anecdotes and targeted bypasses rather than longitudinal measurements of coverage, performance, false-positive rates, containment latency, or resistance to tampering. Nor does it answer how often advanced techniques such as enclave malware, GPU-private storage, firmware C2, or ephemeral COM are used in real intrusions.

Sysmon coverage is notably thin, and XDR appears mostly as an implied correlation problem rather than a directly studied product architecture. Future work could test which combinations of ETW, Sysmon, kernel callbacks, Defender telemetry, network sensors, identity logs, and cloud audit trails remain trustworthy under active manipulation.

Open technical questions include:

- How can telemetry providers authenticate event origin and distinguish legitimate from attacker-injected ETW data?
- Can event pipelines expose capping, loss, queue pressure, and dropped-event counters as first-class detection signals?
- What practical sensors can observe VBS enclave behavior, GPU-private memory staging, firmware-resident activity, or cross-layer driver abuse?
- How should EDR model COM, WinRT, WMI, package managers, management APIs, and AI-agent actions without producing unsustainable noise?
- Can signed-driver and trusted-installer policies express purpose and context rather than treating signature validity as blanket trust?
- How well do ML models retain performance under temporal drift, active evasion, and changes in enterprise command-line behavior?
- What privacy and governance controls are necessary for richer endpoint telemetry, especially when it captures AI prompts, developer secrets, shell sessions, or identity tokens?
- How can developer endpoints be segmented so that compromise does not automatically expose production, client, and package-publishing infrastructure?

Several minor records have weaker or indirect ties to EDR but remain relevant to endpoint attack surfaces. Finally, records on script obfuscation, AI-assisted malware, and custom evasion loaders illustrate the continuing user-mode contest. Together with the COM, WMI, enclave, driver, and GPU records, these show that endpoint defense must cover both familiar process-injection tradecraft and execution paths that bypass conventional process-centric assumptions.
