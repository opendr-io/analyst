# Topic: Application security

## Meta-Summary

The records portray application security as an increasingly architectural discipline. Conventional weaknesses—broken authorization, injection, unsafe deserialization, parser inconsistencies, request smuggling, session theft, insecure file handling, and business-logic abuse—remain highly productive. New technology rarely replaces these bugs; it creates additional translation layers, trust handoffs, and privileged automation through which old weaknesses can reappear with greater reach.

Three developments dominate the collection:

1. **Application boundaries are becoming more distributed and ambiguous.** Modern applications span browsers, APIs, microservices, SaaS integrations, identity providers, mobile clients, CI/CD systems, cloud middleware, and IoT backends. Vulnerabilities often emerge where two components interpret the same state differently.
2. **AI agents are becoming application-security principals.** Once models can browse, call tools, read files, alter workflows, or act with user credentials, prompt injection becomes an entry point into familiar app-layer impacts such as IDOR, SSRF, command execution, data exfiltration, persistence, and account takeover.
3. **AI-assisted vulnerability discovery is moving from demonstrations to production pipelines.** The most credible systems do not rely on unconstrained model judgment. They combine models with static or dynamic analysis, deterministic validators, exploit reproduction, specialized agents, and human review.

The defensive direction is similarly clear: move away from report-by-report patching toward secure defaults, browser-enforced controls, strict authorization invariants, isolation of untrusted execution, transactional parsing, least-privilege tool design, and automated elimination of whole bug classes.

## Research Landscape

The collection is dominated by conference abstracts from Black Hat, DEF CON, BSides Las Vegas, CAMLIS, Prompt||GTFO, and [un]prompted, chiefly from 2025–2026. Most are practitioner or offensive-research presentations rather than peer-reviewed papers. They commonly promise demonstrations, exploit chains, tools, CVEs, or bug-bounty outcomes. Consequently, the records are especially useful for mapping emerging attack surfaces and practitioner methods, but less reliable for independently confirming every prevalence or performance claim.

The material spans several overlapping forms of application security:

- **Web and API security:** access control, request smuggling, cache poisoning, XSS, GraphQL, REST, browser security, OAuth, session handling, and business logic.
- **Source and binary analysis:** SAST, taint analysis, fuzzing, formal methods, LLM-assisted review, exploit generation, and vulnerability validation.
- **Application-adjacent platforms:** mobile and desktop apps, middleware, CI/CD, SaaS systems, browser extensions, game clients, AI runtimes, and IoT management applications.
- **Product-security operations:** bug bounty triage, vulnerability prioritization, secure coding education, threat modeling, and class-level remediation.
- **AI-integrated applications:** prompt injection, tool abuse, agent orchestration, MCP servers, coding agents, AI browsers, and AI-assisted security testing.

The strongest records provide concrete sample sizes, named tools, CVEs, measured outcomes, or reproducible methods. Examples include the microservice taint analysis evaluated against 30 applications and associated with 59 claimed zero-days [record_id:69], the DOM-clobbering study reporting 497 gadgets and 19 CVEs [record_id:1947], CodeQL enhancements tested over 5,000 repositories [record_id:24], the 14-implementation healthcare OAuth comparison [record_id:2723], and the behavioral audit of 189 offensive-agent runs with 68,049 traced spans [record_id:2772].

Other records are short event descriptions, panels, career workshops, biographies, or broad discussions. These provide contextual evidence but little technical substantiation. The collection therefore supports strong conclusions about recurring concerns and research directions, but not precise estimates of ecosystem-wide prevalence.

## Major Themes And Trends

### Old vulnerabilities persist inside new architectures

A central pattern is the reappearance of established bug classes in systems marketed as modern or intrinsically safer. Connection-based OAuth services recreate session fixation, open redirect, confused-deputy, XSS, and cross-window attacks because proprietary token abstractions weaken standard OAuth assumptions [record_id:3]. AI developer tools discard familiar privilege boundaries in pursuit of convenience [record_id:46], while agent frameworks allow prompt-controlled data to reach orchestration state, routing, memory, or native parsers [record_id:2648].

This pattern extends beyond AI. Enterprise middleware exposes internal execution surfaces through routing, dispatcher behavior, unsafe object construction, token failures, and template expansion [record_id:2589]. String-to-object conversion can reproduce deserialization-like RCE even when traditional serializers have been hardened [record_id:2605]. WebAssembly and Pyodide “sandboxes” fail when reflection or `ctypes` can cross into the JavaScript host [record_id:2878]. Security scanners themselves become supply-chain execution environments when they process attacker-controlled repositories without isolation [record_id:2625].

The recurring lesson is that security claims attached to one layer—safe model loading, correct cryptography, sandboxing, authentication, or standards compliance—do not secure the complete application path.

### Interpretation mismatches are a foundational vulnerability source

Many high-impact findings arise because multiple components disagree about syntax, normalization, lifecycle, origin, or trust. Unicode normalization and conversion differences allow WAF and backend bypasses leading to XSS, SSTI, response splitting, redirects, or RCE [record_id:13]. Later work broadens this into a distributed parsing problem involving UTF-8 validation, browser and WAF canonicalization, database collation, cookie parsing, and LLM preprocessing [record_id:2604].

HTTP desynchronization is the clearest protocol example. Request smuggling persists because front ends, back ends, proxies, CDNs, and browsers disagree about message boundaries [record_id:19]. CRLF-based techniques extend desync attacks even to nominally RFC-compliant proxy chains [record_id:2587]. HTTP/2 and HTTP/3 research similarly targets disagreement about stream lifetime, ordering, buffering, and race semantics [record_id:2651] [record_id:2881].

The same principle appears in Windows path interpretation [record_id:1959], Android intent resolution [record_id:1982], cache keys [record_id:2999], rejected parser inputs that mutate state before final validation [record_id:2786], compiler transformations that introduce TOCTOU behavior [record_id:2683], and agent workflows where validation and execution interpret the same state differently [record_id:2644].

### Authentication is a system, not a ceremony

The records repeatedly challenge claims that a particular authentication technology is “phishing-proof” or self-sufficient. OAuth failures commonly stem from missing state, poor discovery-document validation, token replay, or confusion between authentication and authorization [record_id:20] [record_id:2383]. Account recovery remains a parallel authentication mechanism and can undercut passwordless security [record_id:70].

Passkeys and FIDO2 receive especially sustained scrutiny. CTAP client impersonation and API confusion can reset authenticators, wipe credentials, or track users [record_id:1992]. WebAuthn calls can be proxied or modified when client-side code is compromised and relying parties omit attestation or metadata checks [record_id:1997]. Synced passkeys may still be phished [record_id:2080], while flawed server-side verification can enable “Pass-the-Passkey” attacks resembling relay or pass-the-hash techniques [record_id:2590]. The broader 2026 survey argues that the ceremony may be sound while storage, synchronization, recovery, downgrade paths, and relying-party integration remain vulnerable [record_id:2945].

Sessions and identity aliases are equally fragile. Browser-extension clickjacking can expose passwords, TOTP values, credit-card details, and passkey operations [record_id:1851]. Chrome cookie encryption can be bypassed under some attacker conditions [record_id:2543]. “Private” inbound email addresses may function as unrecognized API keys [record_id:2774], while inconsistent email canonicalization and recovery behavior can route login links and reset messages to unintended recipients [record_id:2776].

### Business logic and authorization remain difficult to automate

Business-logic weaknesses recur in invitation systems, referral programs, payment and entitlement flows, promotions, account relationships, and APIs. Referral implementations expose races, cookie injection, path traversal, and reward theft [record_id:2089]. Recursive Request Exploits chain interdependent requests to bypass authentication, entitlement, or payment controls [record_id:2107]. Invitation flows can provide persistent access or block legitimate users [record_id:2406]. “Low-severity” logic issues can produce unlimited benefits or direct financial loss despite being downgraded by triage systems [record_id:2730].

GraphQL and REST systems are repeatedly implicated in object-level authorization failures and excessive data exposure [record_id:2018]. Automotive dealer APIs demonstrate the physical consequences of centralized authorization flaws: national administrator access, vehicle reassignment, user impersonation, PII access, and remote vehicle control [record_id:2036] [record_id:2099]. Similar access-control failures affect public transport [record_id:2714], healthcare devices [record_id:3067], and exposed AI tools [record_id:2209].

Automation research increasingly targets these flaws, but the records concede that business context and application state are difficult to infer. Reinforcement-learning agents can model roles, tokens, and state transitions in vulnerable REST and GraphQL environments [record_id:2395], while strict login and resource-access validators enable agents to search for “auth-by-one” errors [record_id:2326]. Yet enterprise API work reports that agents fail when resource relationships and domain context are not established first [record_id:3018].

### AI agents collapse data and authority boundaries

The AI records converge on a simple architectural hazard: agents consume untrusted content while holding access to sensitive data and tools. Calendar invitations, documents, email, web pages, images, tool metadata, logs, and memory can all become instruction channels. A calendar invitation can trigger Gemini agents to exfiltrate data, alter events, operate smart-home devices, or propagate to other agents [record_id:1965]. Agentic browsers can treat hidden HTML or images as instructions, leading to data theft or account takeover [record_id:2583]. MCP metadata can silently redirect reasoning toward local-file access or command execution [record_id:2207].

The collection uses several labels for related patterns—indirect prompt injection, promptware, Parameter-to-Prompt injection, Intent Collision, PleaseFix, tool poisoning, memory poisoning, and trust-handoff failure—but the root issue is consistent. Models cannot reliably distinguish ambient data from authorized instructions, and applications often let model output cross directly into privileged execution.

There is some disagreement about mitigation. Prompt-focused defenses such as spotlighting report large reductions in experimental attack success [record_id:144], and prompt hardening or security-steerability benchmarks show improvements from model choice and targeted patches [record_id:2199] [record_id:2506]. Other records argue that prompt injection cannot be eliminated and should not be treated as the primary security boundary [record_id:58] [record_id:71]. The later architectural position is stronger across the collection: encapsulation, deterministic policy, typed interfaces, capability removal, sandboxing, explicit reauthentication, and strict separation of data from orchestration are more dependable than model alignment alone [record_id:2361] [record_id:2808] [record_id:2819].

### AI-generated code and AI-generated findings require verification

The records distinguish syntactic competence from security competence. Testing across 100 models found that generated code improved syntactically while its secure-code pass rate remained flat; models could often fix a vulnerability when explicitly asked but did not write secure code by default [record_id:2211]. Vibe-coding demonstrations similarly report apparently functional output that fails basic security review [record_id:2568].

The same reliability problem affects offensive output. Unconstrained models produce plausible but false reports, nonexistent endpoints, and broken exploit chains. The dominant response is **proof-oriented automation**:

- exploit validators that accept only demonstrably working results [record_id:79];
- multi-stage static and LLM verification with confidence-based human routing [record_id:2329];
- dedicated skeptic agents, weighted scoring, visual validation, and immutable audit trails [record_id:2931];
- target modeling before testing and mandatory reproduction before reporting [record_id:3027];
- SAST rules used as fast evidence that the alleged vulnerable pattern actually exists [record_id:3044].

The behavioral audit of offensive agents adds an important corrective: agents favor raw HTTP and shell tools, react rather than enumerate, frequently depend on guesses, and are much better at chaining known weaknesses than performing methodical reconnaissance or writing usable reports [record_id:2772]. This aligns with the argument that human advantage is moving upstream toward target selection, organizational inference, and undocumented reconnaissance [record_id:3064].

### Prevention is shifting from individual patches to class-level controls

Several defensive records reject the endless cycle of bounty report, patch, and recurrence. Strict Content Security Policy, Trusted Types, and Fetch Metadata can suppress broad classes of XSS, CSRF, clickjacking, and cross-origin attacks when deployed and monitored at scale [record_id:2433] [record_id:2532] [record_id:2580]. QUACK automatically binds deserialization to inferred class allowlists, blocking an average claimed 97% of potential gadget code in its evaluation [record_id:14]. Seccomp profiles contain application exploits at the syscall boundary [record_id:2456], while PLaTypus proposes module-level control-flow jails with low reported overhead [record_id:2634].

Operational equivalents include deleting dangling DNS during infrastructure teardown [record_id:2829], mapping and expiring abandoned webhooks [record_id:3014], injecting threat models and security requirements into AI coding loops [record_id:2373], and centralizing evaluated security guidance for defensive agents [record_id:2323]. These approaches treat security as an invariant of platforms and workflows rather than a memory exercise for individual developers.

## Methods, Tools, And Approaches Discussed

### Static, semantic, and data-flow analysis

The records show static analysis becoming more customized and hybrid. CodeQL enhancements use LLMs to identify framework-specific sources and sinks, then patch data-flow modeling for reflection, native methods, and value propagation [record_id:24]. MTD joins gateway analysis, service-dependence graphs, and selective context-sensitive taint analysis to follow dangerous data across microservice boundaries [record_id:69]. Tree-of-AST uses a Locate-Trace-Vote process to track flows across files without predefined sources [record_id:82], while “Let LLM Learn” slices code with static analysis and incrementally caches semantic vulnerability knowledge [record_id:72].

Other approaches include iterative retrieval for vulnerable-code discovery [record_id:122], operational taint analysis for Python class pollution [record_id:2922], cryptographic flow extraction and SBOM-like graph visualization [record_id:2186], source-to-sink agent pipelines designed to reduce false positives [record_id:2374], and graph stitching across API definitions, ingress routes, runtime metadata, and source code [record_id:3130].

### Fuzzing, symbolic execution, and exploit generation

Traditional techniques remain important, often enhanced rather than replaced by AI. Orion uses models to choose fuzz targets, generate harnesses and seeds, reproduce crashes, and propose patches [record_id:2137]. Unicode fuzzing uses Shazzer, recollapse, and Burp ActiveScan++ enhancements [record_id:13]. Hulk dynamically identifies DOM-clobbering gadgets and creates complete exploits [record_id:1947].

Binary-oriented systems combine lifting, taint filtering, formal verification, directed fuzzing, and concolic execution [record_id:2882]. BinWhisper integrates LLM reasoning with static analysis and dynamic debugging [record_id:63]. Other work emphasizes constrained exploit engineering, including delimiter smuggling against NAS devices [record_id:1850], restricted-byte ROP for Tinyweb [record_id:2704], arbitrary file-write escalation across frameworks [record_id:2981], and PHP exploitation using heap manipulation or use-after-free primitives [record_id:2680] [record_id:2948].

### Black-box web and API testing

Burp Suite remains the dominant testing environment, supplemented by ZAP, SQLmap, Caido, Frida, Ghidra, CodeQL, Nuclei, HTTPX, and custom extensions. Regex-based recon is proposed for mining JavaScript, identifying endpoints and secrets, and testing CORS, `postMessage`, SSRF, and redirects [record_id:1921]. RRE is implemented as a Burp extension for recursively mapping dependent requests [record_id:2107]. BugTraceAI generates SQLi, XSS, JWT, and SSTI payloads, cross-checks models, and exports to SQLmap [record_id:2182]. Burp extensibility through BChecks, Bambdas, and full extensions is itself treated as an AppSec skill [record_id:2773].

Mobile and IoT assessments commonly combine decompilation, dynamic instrumentation, TLS interception, and protocol reverse engineering. Frida and Burp are used to bypass pinning and decrypt application-layer traffic [record_id:2702]. Burp requests and Ghidra disassembly support router exploitation [record_id:1990]. Android attestation research includes tooling for testing certificate-chain parsing and PKI assumptions [record_id:74].

### Agentic offensive systems

Architectures vary from relatively unconstrained model operators to deterministic, tool-governed pipelines. One approach assigns models reconnaissance tasks and maps relationships in Neo4j using BBOT, Nuclei, and HTTPX [record_id:2194]. Another advocates “agents on rails,” where models reason over evidence but binaries alone touch the target [record_id:3092]. Hackbot design guidance emphasizes narrow roles, context engineering, output parsing, auditability, and cost control [record_id:3068].

Validation is the key differentiator. Strict exploit or authentication oracles support autonomous retries without increasing human review [record_id:79] [record_id:2326]. Feedback-driven verification uses dedicated agents at each phase to correct failures in Android and Chrome analysis [record_id:2628]. Synthetic-vulnerability injection systems ship each injected bug with a proof script [record_id:2344]. These methods collectively suggest that models are most useful as planners and semantic reasoners inside a deterministic evidence pipeline.

### Defensive application-security programs

The operational records recommend integrating open-source tools such as Trivy, GitLeaks, Checkov, ZAP, and OpenGrep into IDE, pre-commit, and CI/CD workflows [record_id:2440]. Risk-based authentication combines heuristics and anomaly detection while attempting to preserve user experience [record_id:126]. Browser and reverse-proxy defenses include fingerprinting, traffic analysis, and bot detection rather than static IP blocklists [record_id:37] [record_id:1948] [record_id:2019].

Bug-bounty program methods emphasize reproducible reports, clear business-impact framing, researcher communication, duplicate detection, safe automated reproduction, and turning confirmed findings into variant hunting and SDLC controls [record_id:1909] [record_id:1928] [record_id:2743]. The records warn, however, that rising AI-generated report volume can overwhelm maintainers unless platforms enforce evidence quality [record_id:2967] [record_id:3044].

## Notable Talks, Records, And Evidence

Several records stand out for breadth or unusually concrete evidence.

- **Windows HTTP services:** The claim of more than 100 critical pre-authentication vulnerabilities across IIS, ADFS, ADCS, Hyper-V, Kerberos, WSUS, WinRM, RDP, and other services is one of the collection’s broadest vulnerability-pattern studies, though the abstract alone does not enumerate the cases [record_id:11].
- **HTTP desynchronization:** The 2025 and 2026 sequence—from HTTP/1.1 request smuggling [record_id:19], through CRLF-powered attacks [record_id:2587], to AI-generated desync techniques [record_id:2594]—illustrates sustained, cumulative research rather than a single bug disclosure.
- **Microservice taint analysis:** MTD reports evaluation on 25 popular open-source and five industrial applications, 59 high-risk zero-days, 31 CVEs in open source, and 20 industrial findings [record_id:69]. This is among the strongest quantitative claims in the set.
- **DOM clobbering:** Hulk’s reported 497 zero-day gadgets in the Tranco Top 5,000, more than 200 HTML-injection sites, full chains in widely used applications, and 19 CVEs make it a representative example of systematic web measurement plus automated exploitation [record_id:1947].
- **OAuth in production healthcare APIs:** Testing 14 implementations and identifying four distinct error-discriminator patterns, including a product-level pattern across many hospital deployments, provides useful cross-vendor evidence [record_id:2723].
- **Agent-security demonstrations:** Calendar-invitation attacks against Gemini [record_id:1965], framework-level prompt-to-shell paths [record_id:2648], retailer assistant tool execution [record_id:2641], agent-browser takeover [record_id:2667], and agent-to-agent compromise through Cloudflare and Sentry data [record_id:2951] collectively show that AI exploitation increasingly targets application composition rather than model output alone.
- **Empirical agent evaluation:** The 189-run behavioral audit is unusually valuable because it measures process, not merely solve rate [record_id:2772]. Its observations about poor enumeration, guessing, dead tools, and weak reporting temper more promotional claims of autonomous performance.
- **Secure code generation:** The 100-model comparison supplies evidence that syntax quality and security quality are not advancing together [record_id:2211].
- **AI vulnerability discovery:** Claims range from over 200 web-app zero-days [record_id:79], to 100-plus AI-infrastructure vulnerabilities [record_id:2329], 12 OpenSSL zero-days [record_id:2350], and 100-plus Android and Chrome findings [record_id:2628]. These support the trend, but independent verification and normalized benchmarks remain limited.
- **Class-level web defense:** Google’s reported rollout of strict CSP, Trusted Types, and compile-time protections across hundreds of products offers a rare large-organization defensive case study [record_id:2532].
- **Application-to-physical impact:** Dealer-platform API flaws affecting vehicle control [record_id:2036], smart-bus compromise [record_id:2121], fertility-device authentication failures [record_id:3067], and public-transport control-plane access [record_id:2714] demonstrate that application-layer weaknesses increasingly cross into safety and privacy domains.

## Gaps, Limits, And Open Questions

### Evidence is often abstract-level and self-reported

Most records are conference descriptions, not full technical papers. Claims about zero-days, exploit success, vulnerable percentages, bounties, and performance should be treated as reported results until source code, advisories, datasets, or papers are reviewed. Some abstracts provide strong details but no baselines; others use promotional language without enough methodology to assess false negatives, scope, or reproducibility.

### Benchmark quality is unresolved

Agent and LLM vulnerability-discovery systems are evaluated on incompatible targets: CTFs, open-source repositories, production bug bounties, synthetic applications, or private codebases. Solve rate can conceal guessing, weak methodology, or poor reporting [record_id:2772]. Open questions include:

- How should agents be measured on reconnaissance completeness, recovery from wrong assumptions, exploit stability, reporting quality, and cost?
- How well do strict validators generalize to logic flaws whose success cannot be reduced to a simple oracle?
- How much apparent performance results from benchmark contamination or memorized public vulnerability patterns?
- Can synthetic-vulnerability systems produce representative distributions without teaching scanners artifacts of the injector?

### AI defense claims need comparative testing

Spotlighting and prompt patching report meaningful improvements [record_id:144] [record_id:2199], while architectural talks argue that prompt-level defenses cannot provide a security boundary [record_id:58] [record_id:2808]. These positions are not necessarily contradictory—prompt controls may reduce frequency while architecture limits impact—but the collection lacks long-running comparative studies across models, modalities, multilingual inputs, tool chains, and adaptive attackers.

### Authorization remains under-formalized

Access-control and business-logic bugs are common, yet most defenses remain application-specific. The records do not establish a general method for deriving authorization invariants from product requirements, proving their implementation, or continuously checking them across distributed services. MeshLens, attack-tree generation, resource-relationship modeling, and strict auth validators point toward possible solutions, but no mature consensus appears.

### Secure deployment and remediation are less covered than exploitation

Many talks stop at vulnerability discovery or proof of concept. There is less detail on patch rollout, backward compatibility, telemetry, abuse detection, or long-term regression prevention. This is particularly important for IoT, enterprise middleware, mobile ecosystems, browser protocols, and agent frameworks where vulnerable versions may persist for years.

### Human and organizational effects need more study

Bug-bounty programs face rising submission volume and AI-generated noise, while developers increasingly rely on AI-generated code. The collection identifies these problems but provides limited longitudinal evidence about staffing, remediation latency, researcher incentives, or whether automated triage introduces systematic severity bias. Legal boundaries for reconnaissance and public testing also remain important [record_id:3037].
